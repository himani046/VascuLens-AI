# VascuLens AI

**Multimodal AI Hackathon 2026 · Track A — Cardiovascular Risk Visualization & Prediction**

VascuLens AI is a research prototype that brings together clinical machine learning, coronary image-segmentation experiments, and interactive 3D heart visualization. It is designed to demonstrate how model outputs can be explored alongside vessel-specific context in an explainable dashboard.

> **Clinical safety:** Educational/research prototype only. It is not clinically validated and must not be used to diagnose, rule out disease, or guide treatment. CAD/vessel probabilities are model estimates, not confirmed stenosis measurements. Schematic 3D overlays do not imply patient-specific lesion localization.

## Track A scope

- Predict overall CAD (Cath) and vessel labels (LAD, LCX, RCA) from clinical, lab, ECG, and echocardiographic features.
- Exclude all outcome columns (Cath, LAD, LCX, RCA) from every input matrix to avoid target leakage.
- Evaluate with accuracy, balanced accuracy, precision, recall/sensitivity, specificity, F1, ROC-AUC, average precision, and Brier score where appropriate.
- Explore the coronary lumen segmentation pathway separately with a U-Net starter notebook.
- Inspect the heart/vessels in a React + Three.js interface with vessel selection, orbit controls, and risk coloring.
- Surface feature contribution/importance and document data/model limitations.

## Quick start

### 1) Backend

Python 3.10+ is recommended.

```bash
cd backend
python -m venv .venv
# macOS/Linux
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Put the UCI Extension of Z-Alizadeh Sani workbook/CSV in backend/data/ or use the dataset path expected by the training script. Read backend/train.py before training. Then run:

```bash
python train.py --help
uvicorn app:app --reload --port 8000
```

The training pipeline must finish and save model artifacts before inference is available. Do not commit the original dataset or patient-level data to this repository.

### 2) Frontend

```bash
cd frontend
npm install
cp .env.example .env
npm run dev
```

Set VITE_API_BASE_URL=http://localhost:8000 in frontend/.env. The default front-end visual uses a schematic heart; replace it with a properly licensed anatomical mesh before representing the scene as anatomically faithful.

## Notebooks and reproducibility

Open the clinical model notebook in Kaggle and attach the original UCI workbook as a Kaggle input. Run all cells to produce per-target holdout metrics and serialized artifacts. The notebook has not been verified on every copy/layout of the dataset. Verify target mappings and output metrics before using them in the submission report.

The image notebook is a segmentation starter for compatible ImageCAS volume/mask files; it does not predict patient-level CAD and does not establish stenosis from clinical features. Do not join the tabular and CT data by row order or call it joint multimodal fusion unless patient-level paired data and target alignment are available.

## Evaluation reporting

No accuracy target (including 95%) is guaranteed. Report only metrics generated by the stated validation split. The dataset is small (303 records); use stratified evaluation, keep preprocessing inside training folds, disclose uncertainty and avoid overstating generalization. The class probability threshold used for sensitivity/specificity must be stated.

## 3D visualization and risk mapping

LAD, LCX, and RCA are shown as distinct selectable vessel paths. Risk coloring is driven by model probabilities only after trained models are loaded. The current 3D scene is illustrative/schematic and does not provide patient-specific anatomical localization. Vessel-specific notes describe general anatomy, not an individual medical diagnosis.
